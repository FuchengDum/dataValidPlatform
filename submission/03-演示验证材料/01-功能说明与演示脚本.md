# 功能说明与演示脚本

## 1. 演示目标

在有限时间内证明三个结论：

1. 工具能够发现具有业务影响的数据异常，而非仅做字段检查。
2. 工具能够从赛题场景扩展到新的规则包和 JDBC 数据源。
3. AI 能辅助理解和扩展规则，同时保留确定性判定与安全边界。

## 2. 开场陈述

建议开场话术：

> 业务数据错误往往不是一个字段填错，而是订单、支付和库存之间的链路
> 不一致。本工具用可执行规则发现问题，用证据链和受控 AI 帮助核查；
> Web 让用户直接理解结果，CLI 让同样的验证能力进入扩展与自动化场景。

## 3. 第一段：Web 支付对账风险

### 操作步骤

1. 打开 Web 工作台，加载赛题5输入文件。
2. 展示识别摘要与规则模板化工作台，说明规则资产已被加载。
3. 点击 `开始校验`，展示异常总数、严重/警告异常和耗时。
4. 筛选或选择 `R020`，展示订单实付金额与支付金额不一致。
5. 选择 `R029`，展示同订单重复支付风险。
6. 在异常详情区展示实际值、期望值、原因、影响、建议和证据链。
7. 点击 `AI 分析`，展示模型生成或本地降级来源标识。
8. 点击 `只读校验 SQL`，说明草案只用于人工核查，不会自动执行。
9. 导出报告。

### 证明点

- `R020` 表明工具能够执行跨表金额对账。
![alt text](<截屏2026-05-24 23.51.28.png>)
- `R029` 表明工具能识别可能影响资金安全的重复支付。
![alt text](<截屏2026-05-24 23.52.41.png>)
- 详情和证据链表明结果可核验。
- AI 与 SQL 草案表明工具能辅助分析，但不会替代规则判定。

## 4. 第二段：CLI 通用 JDBC 扩展

### 操作步骤

```bash
cd backend
# 执行前确保 java -version 可用
../bin/data-validator lint --config ../examples/generic-jdbc/validator.yml
../bin/data-validator run --config ../examples/generic-jdbc/validator.yml --json --no-report
```

讲解重点：

1. 此处不再使用订单赛题数据，而是 `contract_bill` 与 `payment` 两类业务表。
2. 数据通过 JDBC 只读样例加载，规则使用 YAML 模板资产。
3. `lint` 先检查配置和字段引用，再由 `run` 执行校验。
4. 输出可由脚本消费；退出码 `2` 表示命中严重异常阈值。
5. 当前样例的 H2 初始化脚本路径以 `backend/` 为运行目录解析，该约束应
   在操作说明中保留，避免现场误操作。

### 证明点

- 工具能力可迁移到新的业务表和数据源。
- 通用规则模板减少新增业务校验时的专属代码扩展。
- CLI 为流水线接入提供基础，而非仅服务现场演示。

## 5. 第三段：AI 推荐与安全边界

### 规则候选演示

```bash
bin/data-validator recommend \
  --rules examples/generic-validation/rules.yml \
  --metadata examples/generic-validation/source.yml \
  --output /private/tmp/data-validator-recommendations.json \
  --candidate-rules /private/tmp/data-validator-rules.recommended.yml
```

说明：

- 规则片段能够覆盖的场景优先复用片段。
- AI/本地推荐用于补充生成候选，结果需由人审阅。
- 候选文件写入新路径，不覆盖正式规则资产。

### 安全边界展示

- 展示 Web SQL 草案的 `generatedByAi`、`source` 或 warning 标识。
- 展示系统对非只读 SQL、危险关键字或模型非法返回的拒绝/降级原则。
- 明确 JDBC 仅主张只读接入，AI 不自动执行 SQL 或修改数据。

## 6. 附件复现：Case5 CLI


## 7. 演示结语

建议结语：

> 本工具以确定性规则保证校验可信，以 AI 提升配置和解释效率。Web
> 解决用户看得懂、查得快的问题，CLI 解决规则可扩展和结果可集成的
> 问题，共同形成可运行、可复现、可工程化演进的数据验证工具。
