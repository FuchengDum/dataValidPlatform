# 关键节点、创新点与安全边界说明

## 1. 创新主张

项目创新点不是让 AI 取代业务规则，而是建设“可信规则智能化”闭环：

1. 结构化规则模板将业务核验逻辑沉淀为可执行资产。
2. 确定性执行器确保相同输入和规则得到可复现结果。
3. AI 帮助解释异常和生成候选规则，减少理解与配置成本。
4. Web 与 CLI 将同一能力分别带给业务核查和工程化扩展场景。

## 2. 创新证据矩阵

| 创新点 | 可展示证据 | 证明结论 |
|---|---|---|
| 支付风险核查闭环 | Web 中 `R020`、`R029` 详情与证据链 | 不只是字段校验，而是业务链路核查 |
| 模板化规则 | 规则工作台、规则片段库、YAML 规则包 | 新规则优先配置化表达 |
| 通用数据源 | `generic-jdbc` 样例 | 能从赛题场景迁移到新的只读数据源 |
| AI 异常解释 | Web AI 分析及来源标识 | AI 提升理解效率但不负责判定 |
| AI 规则候选 | CLI `recommend` 结果 | AI 辅助扩展，人工控制正式规则 |
| 自动化基础 | CLI JSON/JUnit 与退出码 | 具备进入流水线的基础接口 |

## 3. AI 安全边界

| 风险 | 当前约束 | 展示方式 |
|---|---|---|
| AI 判定不可信 | 最终异常由规则执行器判定 | 演示说明中明确 AI 仅辅助 |
| SQL 可能产生写操作 | SQL 草案仅用于预览，危险输出被拒绝或降级 | 保留只读草案与降级来源截图 |
| AI 候选污染正式规则 | 推荐只输出候选文件，不覆盖正式规则包 | 展示候选输出路径与人工确认说明 |
| 模型不可用 | 返回本地规则化分析或推荐 | 同时准备模型结果和本地降级证据 |

只读 SQL 安全约束包括：仅允许 `SELECT`，拒绝多语句、注释、
`SELECT *`、`FOR UPDATE`、危险写入关键字和危险函数。

## 4. JDBC 与数据安全边界

- CLI JDBC 样例用于展示只读接入；真实业务库场景应使用只读账号。
- SQL 数据源模式要求显式声明字段，不以任意 SQL 写入方式扩展能力。
- 密码通过环境变量传入，不写入源码或提交样例。
- Web 的真实生产业务库输入尚未作为当前交付能力。

## 5. 工程化边界

CLI 已实现可供流水线消费的基础结果形态和退出码语义，但以下能力仍是
后续路线：

- 独立 `gate-summary` 文件。
- 完整规则覆盖摘要和趋势展示。
- 提交仓库内的正式 CI workflow 模板与阻断流程。

因此材料使用“具备质量门禁接入基础”的表述，不使用“已建成质量门禁”
的表述。
