# 通用数据验证工具系统设计与技术路线（提交版）

## 1. 文档说明与状态口径

### 1.1 文档目的

本文档描述通用数据验证工具当前提交版本的系统设计、技术路线、实现边界和
可复现证据。产品目标、验收口径和状态边界以
`02-通用数据验证工具产品需求文档-提交版.md` 为准；架构细节综合参考 Web
设计/总技术文档、CLI 演进计划和 Case5 复现记录，并以当前源码和实际核验
结果校正历史设想。

当前产品采用双入口形态：

| 入口 | 面向用户 | 核心任务 | 当前价值证明 |
|---|---|---|---|
| Web 工作台 | 业务/测试用户 | 加载赛题资产、发现异常、理解证据、导出结果 | 赛题5支付核查闭环，重点展示 `R020` 与 `R029` |
| 通用 CLI | 开发/工程化用户 | 校验配置和规则包、接入只读数据源、消费机器结果、扩展规则 | 非订单 JDBC 样例与 Case5 固定复现 |

### 1.2 状态定义

| 状态 | 定义 | 本文使用方式 |
|---|---|---|
| `已实现` | 代码存在，且具备当前版本的可运行或可核验事实 | Web 核查链路、CLI 执行、模板规则、辅助服务和报告输出 |
| `接入基础` | 已提供技术输出或接口形态，但尚未形成完整生产/流程能力 | CLI JSON/JUnit/退出码对接流水线 |
| `后续规划` | 已明确演进方向，但不是本次交付成果 | Web 真实业务库输入、完整质量门禁和治理能力 |
| `非本次承诺` | 当前提交不得视为已交付的能力 | Excel 报告、AI 自动判定/修复、生产级数据平台能力 |

### 1.3 事实约束

1. 异常判定由确定性规则执行完成，AI 不参与最终判定。
2. Web 与 CLI 共用产品原则和部分模板执行能力，但当前使用不同规则入口，
   按各自链路验收，不声明异常集合完全一致。
3. Web 当前上传 Excel 中的规则与说明资产，业务数据从 H2 V3 seed 表读取；
   Web 真实业务数据库输入尚未交付。
4. 当前 Web 页面演示使用 Markdown 报告导出；后端支持 Markdown/HTML；
   Excel 格式报告不是本次成果承诺。

## 2. 产品目标与双入口总体架构

### 2.1 设计目标

系统以“规则确定性判定、异常证据可追溯、智能辅助可控制”为主线：

1. 通过 Web 工作台让业务/测试用户直观完成赛题业务异常核查。
2. 通过 CLI 规则包与只读数据源能力证明工具可扩展到新的业务数据。
3. 通过结构化模板降低新增规则对业务编号特例代码的依赖。
4. 通过只读约束、来源标识、降级策略和人工确认控制 AI 与数据接入风险。

### 2.2 逻辑架构

```text

            +----------------------+----------------------+
            |                                             |
       Web 交互核查入口                              CLI 工程化入口
    Vue 3 + Vite 单页工作台                 bin/data-validator / .cmd
            |                              init / lint / run / validate
            |                                     / recommend / --version
            v                                             v
    Spring Boot REST API                       Spring Boot 非 Web 模式
 Upload / Validation / Finding / Rule             GenericValidationCli

            |                                             |
            v                                             v

            |                                             |
            +----------------------+----------------------+
                                   |

```

### 2.3 运行入口边界

后端主程序 `DataValidatorApplication` 依据首个命令参数决定运行模式：

| 启动方式 | 运行模式 | 当前实现含义 |
|---|---|---|
| 不携带 CLI 命令启动 | Web 模式 | 启动 REST API、H2/Flyway 与 Web 支撑服务 |
| `run` / `validate` / `lint` / `recommend` / `init` / `--version` | CLI 模式 | 以 `WebApplicationType.NONE` 启动，不暴露 Web 服务 |

该设计让 Web 与 CLI 位于同一后端工程，能够复用领域类型、模板执行器和
辅助逻辑，同时允许两条产品链路独立维护输入资产和验收结果。

## 3. Web 工作台系统设计

### 3.1 端到端数据流

```text
用户上传赛题5 Excel
  -> UploadController / ExcelImportService 校验必需 sheet 并读取规则、场景资产
  -> BusinessTableDataProvider 从 H2 V3 seed 读取 5 张演示业务表
  -> 保存 dataset、table snapshot、rule definition、rule binding
  -> 用户查看规则绑定或应用人工确认后的推荐
  -> ValidationService 创建任务并执行确定性规则
  -> 保存 finding 与 evidence，查询汇总/详情
  -> 用户按需请求 AI/本地分析或只读 SQL 草案
  -> ReportService 生成报告文件并提供下载
```

Excel 导入要求包含 `业务规则库`、`字段约束说明`、`关联逻辑说明` 和
`校验场景覆盖矩阵` 等说明/规则 sheet。当前代码不以 Excel 业务数据 sheet
作为 Web 校验数据真源，而是由 H2 V3 seed 固化演示业务表数据，以保障复现。

### 3.2 功能模块与需求映射

| PRD 需求 | 用户能力 | 核心实现 | 当前状态 |
|---|---|---|---|
| `WEB-FR-01` | 加载赛题资产并展示识别摘要 | `UploadController`、`ExcelImportService`、`BusinessTableDataProvider` | `已实现` |
| `WEB-FR-02` | 发起规则校验并查看汇总 | `ValidationController`、`ValidationService` | `已实现` |
| `WEB-FR-03` | 按规则/表/等级筛选异常并查看证据 | `FindingController`、`validation_finding`、`finding_evidence` | `已实现` |
| `WEB-FR-04` | 核验订单支付、商品明细、库存履约链路 | `TemplateRuleExecutor` 与内置规则兜底 | `已实现` |
| `WEB-FR-05` | 请求异常分析和只读 SQL 草案 | `AiAssistController`、`AiAssistService` | `已实现`，辅助性质 |
| `WEB-FR-06` | 生成并下载核验报告 | `ReportController`、`ReportService` | `已实现`，不含 Excel 报告 |

### 3.3 规则绑定与确定性执行

Web 导入链路从 Excel 规则资产生成 `RuleDefinition`，并由
`ExcelImportService` 为能够结构化表达的规则创建默认 `TEMPLATE` 绑定。
执行时 `ValidationService` 遍历数据集规则：

1. 规则绑定为 `executorType=TEMPLATE` 时，交给 `TemplateRuleExecutor`。
2. 未绑定模板或需兼容历史行为时，进入内置 `R001-R030` 规则分支。
3. 校验任务、异常结果和证据均保存在系统库中，供列表、详情与报告使用。

当前评审演示重点为支付链路：

| 规则 | 核查含义 | 当前可观察证据 |
|---|---|---|
| `R020` | 订单实付金额与成功支付汇总是否一致 | `ORD002` 实付金额 `1580`，支付汇总 `3160` |
| `R029` | 同一订单是否存在重复成功支付 | `ORD002` 成功支付次数 `2`，期望 `<= 1` |

### 3.4 前端交互与报告

前端为 Vue 3 + Vite 单页工作台，通过 `frontend/src/api/client.js` 消费 REST
接口，当前覆盖上传、校验、汇总卡片、规则模板绑定、异常筛选/详情、辅助
分析及报告下载。

| 报告能力 | 当前实现 |
|---|---|
| 页面演示导出动作 | 固定请求 `MARKDOWN` 报告 |
| 后端文件生成 | `ReportService` 支持 Markdown 和 HTML 后缀报告 |
| Excel 格式报告 | `非本次承诺`，当前代码未落地 |

### 3.5 Web 当前边界

`DataSourceController` 暴露的 `/api/datasources/database-table` 与
`/api/datasources/sql-query` 当前仅返回预留能力提示。Web 链路证明的是
受控演示环境中的交互核查能力，不表示已完成真实生产数据库接入、权限治理
或数据抽取流程。

## 4. CLI 通用化系统设计

### 4.1 定位与执行流

CLI 作为旁路通用验证内核，不替换现有 Web 演示链路。其目标是让开发或
工程化用户通过配置资产和只读数据源执行确定性校验，并将结果交由脚本、
测试平台或人工审阅。

```text
init jdbc 生成接入起点 / 人工准备 validator.yml、source.yml、rules.yml
  -> lint 校验 schemaVersion、模板参数、表字段引用和安全配置
  -> run 或 validate 加载数据源和结构化规则包
  -> GenericValidationRunner 调用 TemplateRuleExecutor 产生 findings
  -> 输出摘要、报告文件和退出码
  -> 可选 recommend 生成需人工审阅的候选规则包
```

### 4.2 命令与实现模块

| 命令 | 用户任务 | 核心实现 | 当前状态 |
|---|---|---|---|
| `init jdbc --output <dir>` | 生成 JDBC 接入样板 | `GenericValidationCli`、`GenericJdbcInitTemplates` | `已实现` |
| `lint --config ...` | 检查组合配置 | `GenericValidationCli`、`GenericValidationLinter` | `已实现` |
| `lint --rules ... --metadata ...` | 检查规则包和字段引用 | `GenericValidationLinter` | `已实现` |
| `run --config ...` | 使用组合配置执行校验 | `GenericValidationRunner` | `已实现` |
| `validate --rules ... --source ...` | 直接组合规则包与数据源执行 | `GenericValidationRunner` | `已实现` |
| `recommend --rules ... --metadata ...` | 生成规则模板推荐及可选候选包 | `GenericValidationCli`、`AiAssistService` | `已实现`，需人工审阅 |
| `--version` | 查询版本 | `GenericValidationCli` | `已实现` |

### 4.3 配置资产与数据源

| 资产或数据源 | 作用 | 设计边界 |
|---|---|---|
| `validator.yml` | 组合数据源、规则包、报告与失败等级策略 | 当前支持 `schemaVersion: 1` |
| `source.yml` | 定义逻辑表、字段、主键和数据源配置 | 支持 inline、文件和 JDBC 只读读取 |
| `rules.yml` | 定义模板规则、严重等级和业务说明 | 新规则优先通过结构化模板表达 |
| JDBC 表或 SQL | 读取业务数据或派生规则字段 | 只允许显式字段的单条只读查询 |
| 候选规则包 | 保存 `recommend` 可审阅结果 | 只写新路径，不覆盖正式规则包 |

CLI 通用内核通过 `GenericRuleAssetLoader` 加载资产，通过
`GenericDataSourceProvider` 选择输入源，并统一交给 `TemplateRuleExecutor`
执行。因此非订单领域规则不需要新增 `R001-R030` 式 Java 编号分支。

### 4.4 输出契约与样例证明

| 输出或语义 | 当前实现 |
|---|---|
| 人工可读输出 | Markdown、HTML 报告 |
| 机器可读输出 | JSON 报告/摘要、JUnit XML |
| `--json --no-report` | 仅输出摘要且不落报告，适于脚本采集 |
| 退出码 `0` | 执行成功，未触发阻断等级异常 |
| 退出码 `1` | 工具执行失败 |
| 退出码 `2` | 校验成功执行且发现严重异常 |
| 退出码 `3` | 命令、配置或规则非法 |

| 样例 | 证明目标 | 当前固定结果 |
|---|---|---|
| `examples/generic-jdbc/` | 通用模板可用于非订单 JDBC 场景 | 2 条规则、2 张表、3 行、1 条严重异常，退出码 `2` |
| `examples/case5-seed/` | CLI 可使用 YAML 规则包复现赛题规模校验 | 30 条规则、5 张表、70 行、68 条异常（严重 60、警告 8），退出码 `2` |

`case5-seed` 使用 V3 seed 初始化业务表并通过只读 SQL 派生规则需要的字段。
Web Excel 导入不读取该样例的 YAML 规则包，因此 CLI Case5 统计不用于替代
Web 当前固定统计。

## 5. 规则执行、AI 与安全设计

### 5.1 Web 与 CLI 执行关系

| 对比项 | Web 工作台 | 通用 CLI |
|---|---|---|
| 规则输入 | Excel 规则/说明资产，导入时生成绑定 | YAML/JSON 结构化规则包 |
| 数据输入 | H2 V3 seed 演示业务表 | inline、文件或 JDBC 只读源 |
| 规则执行 | 模板绑定优先，内置规则兜底 | 模板规则执行链 |
| 共同复用 | `TemplateRuleExecutor` 及结构化模板思想 | `TemplateRuleExecutor` 及结构化模板思想 |
| 验收方式 | 交互核查和证据展示 | 通用样例、机器输出和固定复现 |

### 5.2 模板能力

当前模板能力能够覆盖以下类型的常见规则：

| 能力类型 | 当前模板示例 | 用途 |
|---|---|---|
| 字段约束 | `NOT_NULL`、`NON_NEGATIVE`、`NUMERIC_TYPE` | 必填、非负、数值类型 |
| 单行关系 | `FIELD_EXPRESSION`、`ROW_EXPRESSION` | 金额关系、状态条件 |
| 关联检查 | `EXISTS_IN_TABLE`、`RELATION_EXISTS`、`JOIN_ASSERT` | 跨表存在和字段断言 |
| 聚合核对 | `AGGREGATION_EQUALS`、`AGGREGATE_ASSERT` | 汇总金额一致性 |
| 重复检测 | `DUPLICATE_CHECK`、`DUPLICATE_ASSERT` | 重复支付等分组异常 |

新增业务规则优先使用现有模板和规则包；只有当新执行语义确实无法表达时，
才应扩展通用模板及参数校验，而非新增业务编号硬编码分支。

### 5.3 AI 辅助边界

`AiAssistService` 当前提供三类辅助能力：

| 能力 | 触发方式 | 边界 |
|---|---|---|
| 异常分析 | Web 用户请求 `/api/ai/findings/{findingId}/analysis` | 生成原因、影响和建议，不改变 finding |
| SQL 草案 | Web 用户请求 `/api/ai/sql-drafts` | 始终返回 `executable=false` 的预览文本 |
| 规则推荐 | Web 推荐接口或 CLI `recommend` | 返回推荐/候选，必须人工应用或维护正式规则 |

`ValidationService.validate(datasetId, enableAiAnalysis)` 当前负责确定性执行和
任务持久化，`enableAiAnalysis` 被记录为任务属性，但执行流程不自动调用 AI
生成或修改异常结果。模型不可用、输出非法或安全校验不通过时，辅助服务
返回 `LOCAL_RULE_BASED` 本地结果或警告。

### 5.4 安全控制

| 风险 | 当前控制 | 代码落点 |
|---|---|---|
| AI 输出被误当作判定 | AI 与规则执行解耦，结果带来源与人工确认语义 | `AiAssistService`、前端展示 |
| Web SQL 草案越权 | SQL 仅供预览，不自动执行；模型结果需满足只读和字段约束 | `AiAssistService` |
| CLI JDBC 读取产生写操作 | 只允许 `SELECT`，拒绝多语句、注释、危险关键字、`SELECT *`、`FOR UPDATE` 和危险函数 | `SqlReadOnlyGuard` |
| 数据库连接可写 | JDBC 连接设置只读属性 | `GenericJdbcDataSourceFactory` |
| 凭证进入配置或源码 | 拒绝明文 `password` 和 URL 敏感参数；MySQL 要求 `passwordEnv` | `JdbcCredentialGuard`、`GenericValidationLinter` |
| 推荐污染正式规则 | 候选只写新文件路径，不覆盖输入规则包 | `GenericValidationCli` |

安全原则在 Web 与 CLI 中保持一致，但具体防护由各自入口实施，不将其误述
为完全相同的调用路径。

## 6. 关键接口、数据模型与输出契约

### 6.1 Web REST API 摘要

所有 Web 成功/失败响应通过 `ApiResponse<T>` 表达，并包含追踪标识。

| 方法 | 路径 | 职责与边界 |
|---|---|---|
| `POST` | `/api/files/upload` | 上传 Excel 并建立数据集摘要 |
| `POST` | `/api/validations` | 针对数据集启动确定性校验 |
| `GET` | `/api/validations/{jobId}/summary` | 返回规则、异常、等级和耗时汇总 |
| `GET` | `/api/findings` | 按任务及筛选条件查询异常 |
| `GET` | `/api/findings/{findingId}` | 返回异常详情和证据 |
| `GET` | `/api/rules?datasetId=...` | 返回规则及绑定信息 |
| `PUT` | `/api/rules/{datasetId}/{ruleId}/binding` | 人工更新并校验规则绑定 |
| `GET` | `/api/rule-templates` | 返回模板能力清单 |
| `GET` | `/api/ai/findings/{findingId}/analysis` | 按需生成或降级返回异常分析 |
| `POST` | `/api/ai/sql-drafts` | 按需生成不可执行的只读 SQL 草案 |
| `POST` | `/api/ai/rule-binding/recommend` | 按需生成模板绑定推荐 |
| `POST` | `/api/reports` | 生成 Markdown/HTML 报告文件 |
| `GET` | `/api/reports/{reportId}/download` | 下载报告文件 |
| `POST` | `/api/datasources/database-table`、`/sql-query` | 当前返回预留提示，非已交付输入能力 |

### 6.2 Web 持久化模型摘要

| 表 | 当前职责 |
|---|---|
| `dataset` | 保存数据集来源、文件名、状态和导入时间 |
| `data_table_snapshot` | 保存逻辑表元数据、表头和行数 |
| `data_row_snapshot` | 兼容历史 Excel 行快照；当前 H2 业务表路径不以其保存业务行 |
| `rule_definition` | 保存数据集下规则定义 |
| `rule_binding` | 保存 `BUILTIN`/`TEMPLATE` 执行方式和模板参数 |
| `validation_job` | 保存校验任务、耗时与 AI 开关记录 |
| `validation_finding` | 保存异常主记录、实际值、期望值、影响与建议 |
| `finding_evidence` | 保存支撑异常判断的证据记录 |
| `report_file` | 保存报告格式、路径和生成时间 |

Flyway `V1` 初始化系统表，`V2` 将规则主键调整为数据集与规则编号组合，
`V3` 初始化当前 Web 与 CLI Case5 使用的演示业务表数据。

### 6.3 CLI 契约摘要

| 契约域 | 内容 |
|---|---|
| 配置版本 | `schemaVersion: 1`，非法版本由 `lint` 判为错误 |
| 数据源 | inline、文件和 JDBC 只读输入 |
| 规则包 | 结构化模板规则及参数，支持当前 Case5 所需中文分类/等级映射 |
| 报告 | JSON、Markdown、HTML、JUnit XML |
| 自动化摘要 | `--json --no-report` 输出规则、异常、耗时、来源摘要和退出码 |
| 推荐结果 | 模板、参数、置信度、warning、diff 和可选候选规则包 |

## 7. 技术路线与交付边界

### 7.1 已实施技术路线

| 阶段 | 技术路线 | 形成的成果 |
