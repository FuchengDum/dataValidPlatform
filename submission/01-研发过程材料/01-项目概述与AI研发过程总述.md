# 项目概述与 AI 研发过程总述

## 1. 项目概述

本项目面向“研发测试提效率”赛道中的业务数据准确性验证问题。赛题5
提供订单、订单明细、商品、支付、库存流水 5 张业务表，以及 30 条规则、
15 个校验场景和 7 条关联逻辑，适合验证数据在真实业务链路中的一致性，
而不是仅检查字段格式。

项目最终形成一款通用数据验证工具：

- Web 工作台服务于测试人员、业务人员，强调直观发现与解释异常。
- CLI 服务于开发和工程化场景，强调规则扩展、数据源接入、可复现运行和
  流水线接入基础。
- 确定性规则引擎负责异常判定，AI 负责推荐、解释和只读核查草案。

## 2. 核心问题与产品价值

传统人工核查需要跨订单、支付、库存等数据反复对账，存在规则分散、
异常定位慢、证据不完整和结果不易复现的问题。本工具将业务规则变为
可执行校验，将异常输出组织为“规则、记录、实际值、期望值、证据、
原因、影响、建议”的核查链路。

评审首个业务案例选择支付对账风险：

1. `R020` 订单实付金额与支付金额不一致，展示跨表金额核对能力。
2. `R029` 同一订单重复支付，展示可能造成资金风险的严重异常。
3. 用户可在 Web 页面查看证据链、触发 AI 分析、生成只读核查 SQL 草案
   并导出报告。

## 3. 研发演进路线

| 阶段 | 解决的问题 | 已形成成果 |
|---|---|---|
| 选题与需求分析 | 找到适合形成完整核验闭环的赛题 | 选题分析、需求文档、验收场景 |
| Web 演示闭环 | 让业务异常可见、可解释、可导出 | Vue 工作台、Spring Boot API、H2 seed、异常详情与报告 |
| 模板化与 AI 辅助 | 从固定校验提升到规则推荐与分析辅助 | 结构化模板、推荐绑定、AI 分析、只读 SQL 草案与降级 |
| 通用 CLI 扩展 | 将能力推广到新的规则包和数据源 | `lint/run/validate/recommend/init`、文件/JDBC 样例 |
| 工程化基础 | 为自动化使用保留稳定接口 | 退出码、JSON/JUnit 输出、Case5 固定复现样例 |

## 4. 双入口产品设计

Web 与 CLI 是同一工具的两种使用方式，而不是两个独立产品。

| 入口 | 目标用户 | 核心价值 | 主要证据 |
|---|---|---|---|
| Web 工作台 | 测试、业务 | 快速理解异常及其业务影响 | 汇总、筛选、详情、证据链、AI/SQL、报告 |
| 通用 CLI | 开发、测试工程化人员 | 扩展规则和数据源，批量或自动化执行 | YAML 规则包、JDBC 样例、lint、JSON/JUnit、退出码 |

当前 Web 与 CLI 的规则资产入口仍有差异：Web 的赛题演示链路使用既有
模板绑定和内置兜底，CLI 的通用路径使用 YAML 规则包。因此材料只主张
二者共同服务通用验证目标，不主张执行结果逐条完全一致。

## 5. AI 使用方式

项目的 AI 使用遵循“辅助而不越权”：

- Web 中，AI 可解释异常原因、影响和建议，并生成用于人工核查的只读
  SQL 草案。
- CLI 中，`recommend` 可在规则片段不足时生成候选规则建议，供人工审阅。
- AI 不参与最终确定性异常判定，不自动覆盖正式规则包，不自动执行 SQL，
  不自动修改业务数据。
- 模型不可用或输出不符合安全要求时，系统返回本地规则化结果或降级草案。

## 6. 当前成果与后续方向

当前成果能够证明：

- 赛题5业务链路可通过 Web 形成可展示的异常核查闭环。
- 非订单领域的 JDBC 数据可通过 CLI 和通用规则模板执行验证。
- Case5 CLI 样例可固定复现 30 条规则与预期异常统计。
- 工具具备向脚本和流水线提供机器可读结果的基础。

后续方向包括完整质量门禁摘要、规则覆盖统计、正式 CI 模板和 Web 通用
规则资产接入。上述方向作为规划呈现，不计入当前已实现成果。
