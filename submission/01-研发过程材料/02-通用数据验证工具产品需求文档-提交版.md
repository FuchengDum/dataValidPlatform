# 通用数据验证工具产品需求文档（提交详细版）

## 1. 文档说明与提交口径

### 1.1 文档目的

本文档用于说明本次评审提交的通用数据验证工具整体产品需求。工具以
赛题5业务数据准确性验证为首个完整业务案例，通过 Web 工作台证明业务
异常核查价值，通过 CLI 证明规则和数据源能够扩展到非订单场景。

本文替代此前的提交版需求摘要，重点回答以下问题：

1. 工具解决什么业务问题，服务哪些用户。
2. Web 与 CLI 两条入口如何共同形成产品闭环。
3. 当前已交付哪些能力，哪些能力仅具备接入基础或属于后续规划。
4. 如何以可复现证据验收产品主张。

本文描述的是本地演示、评审复现和开发/工程化试用场景下的轻量产品，
不将当前成果包装为完整生产级数据质量平台。

### 1.2 状态标签

| 状态 | 定义 | 文档使用原则 |
|---|---|---|
| `已实现` | 已有功能实现，并存在演示、样例或自动验证证据 | 可作为本次验收主张 |
| `接入基础` | 已提供可被脚本或后续能力消费的接口形态，但尚未形成完整产品闭环 | 说明可演进方向，不扩大承诺 |
| `后续规划` | 已识别的产品发展方向，当前未作为交付结果验收 | 与当前功能分开陈述 |
| `非本次承诺` | 当前明确不主张具备的能力 | 不得在成果介绍中写为已交付 |

### 1.3 编号与事实口径

本文使用两类编号：

- `R001-R030`、`S001-S015`、`REL001-REL007` 来自赛题5规则资产，分别
  表示业务规则、校验场景和业务关联逻辑。
- `WEB-FR-xx`、`CLI-FR-xx`、`RULE-FR-xx`、`AI-SAF-xx`、`NFR-xx`
  为产品需求编号，用于需求与验收证据追踪。

Web 与 CLI 属于同一产品的两种使用方式，但当前采用不同规则资产入口：
Web 使用赛题演示链路和既有模板绑定/内置兜底，CLI 使用 YAML 规则包与
通用模板执行链路。因此两条链路按各自固定证据验收，不声明异常记录或
统计值逐条一致。

## 2. 背景、痛点与产品价值

### 2.1 赛题背景

赛题5聚焦业务数据准确性保障。输入案例覆盖订单、订单明细、商品、支付
和库存流水 5 张业务表，以及 30 条业务规则、15 个校验场景和 7 条业务
关联逻辑。其核心问题不是简单读取数据，而是验证数据是否符合真实业务
事实，例如：

- 订单实付金额是否与成功支付汇总一致。
- 商品价格、订单明细金额与库存扣减是否符合业务约束。
- 同一订单是否发生重复支付，或下架商品是否仍发生出库。

### 2.2 用户痛点

| 痛点 | 典型表现 | 产品应提供的帮助 |
|---|---|---|
| 规则分散 | 规则位于文档、人工 SQL 和个人经验中，难以重复执行 | 将规则沉淀为可执行校验资产 |
| 跨表核查复杂 | 支付、明细、库存需要聚合和关联比对 | 输出异常及其关联证据链 |
| 结果难理解 | 只知道字段错误，不清楚业务影响和核查方向 | 展示实际值、期望值、原因、影响和建议 |
| 过程难复现 | 不同人员手工核查容易得到不同结论 | 固化样例、规则资产、报告与机器输出 |
| 新场景接入成本高 | 每增加一种业务表或规则都可能要求改代码 | 通过 CLI 配置、规则模板和片段复用扩展 |

### 2.3 产品价值目标

工具旨在实现以下价值目标：

1. 将关键业务规则变为稳定可执行的校验流程，减少人工跨表对账步骤。
2. 通过异常证据链和辅助分析，降低问题理解和人工复核难度。
3. 通过固定样例、结构化规则资产和机器可读结果，提升复现能力。
4. 通过通用 CLI 和模板规则，为新业务数据源与规则包提供接入基础。

当前尚未完成两类目标用户的真实易用性试用，因此本文不声明已产生量化
效率提升；易用性价值以待完成的试用任务和观察结果进行验证。

## 3. 产品定位、目标与成功标准

### 3.1 产品定位

通用数据验证工具是一款**以赛题5验证业务价值、以 CLI 证明通用扩展
能力的轻量数据验证工具**。产品以确定性规则执行为可信基础，以受控 AI
辅助解释和规则扩展，面向本地演示、评审复现和开发/工程化试用。

### 3.2 双入口产品形态

| 入口 | 主要用户 | 核心任务 | 当前价值证明 |
|---|---|---|---|
| Web 工作台 | 业务/测试用户 | 发现异常、理解影响、查看证据、导出结果 | 赛题5支付对账与重复支付核查闭环 |
| 通用 CLI | 开发/工程化用户 | 校验资产、执行规则包、接入只读数据源、消费结果、扩展规则 | 非订单 JDBC 样例与 Case5 固定复现 |

两条入口共享的产品原则如下：

1. 异常判定由确定性规则完成。
2. 输出需要包含足够的异常解释或证据，支持人工核查。
3. AI 只用于解释、草案和候选推荐，不替代规则判定。
4. 当前验收分别使用 Web 演示资产和 CLI YAML 资产，结果不要求一致。

### 3.3 当前版本目标

| 目标 | 需求含义 | 状态 |
|---|---|---|
| 业务核查可展示 | 通过 Web 展示具有业务影响的支付链路异常和证据 | `已实现` |
| 规则执行可扩展 | 通过 CLI 对新的规则包和只读 JDBC 数据源执行校验 | `已实现` |
| 固定结果可复现 | 通过 Case5 CLI 样例核对规则规模和异常统计 | `已实现` |
| 结果可供自动化消费 | 通过退出码、JSON 和 JUnit 等形态供脚本读取 | `接入基础` |
| 智能辅助可控 | AI/本地辅助有来源标识、降级路径和安全约束 | `已实现` |

### 3.4 成功标准与证据链

| 证据链 | 成功标准 | 当前验收证据 |
|---|---|---|
| Web 业务核查闭环 | 能加载赛题资产、执行校验、定位 `R020` 与 `R029`、查看证据和导出报告 | Web/API 验收记录与演示截图材料 |
| CLI 通用扩展 | 能对非订单 JDBC 样例执行 `lint` 和 `run`，检出预设异常 | `examples/generic-jdbc/` 与自动验证记录 |

| 易用性观察 | 两类用户能按说明完成各自任务并反馈阻塞点 | 待真实填写的试用记录表 |

## 4. 用户角色与核心旅程

### 4.1 用户角色

| 角色 | 角色类型 | 关注目标 | 主要入口 |
|---|---|---|---|
| 业务/测试用户 | 主要用户 | 快速发现具有业务影响的数据疑点，理解证据和建议 | Web |
| 开发/工程化用户 | 主要用户 | 使用配置和规则包校验数据，扩展规则并消费机器结果 | CLI |
| 测试负责人 | 利益相关方 | 了解覆盖范围、严重异常分布和复现结论 | Web/报告 |
| 评委 | 验收利益相关方 | 判断产品价值、完整度、通用性和可信边界 | 演示/材料 |

### 4.2 Web 核查旅程

```text
加载赛题资产
  -> 查看业务表、规则和场景摘要
  -> 开始校验
  -> 筛选并定位支付/库存等异常
  -> 查看证据链、原因、影响和建议
  -> 可选查看 AI/本地分析与只读 SQL 草案
  -> 导出报告
```

### 4.3 CLI 接入生命周期

```text
生成或准备数据源与规则资产
  -> lint 校验配置及字段引用
  -> run/validate 执行确定性规则
  -> 读取 stdout、退出码或报告产物
  -> 必要时基于规则片段或 recommend 扩展候选规则
  -> 人工确认后维护正式规则包
```

### 4.4 验收观察任务

| 用户 | 试用任务 | 观察项 | 当前状态 |
|---|---|---|---|
| 业务/测试用户 | 通过 Web 找到支付异常并理解建议 | 是否独立定位 `R020`/`R029`，是否理解证据 | 待真实试用 |
| 开发/工程化用户 | 通过 CLI 校验 JDBC 样例并理解扩展方式 | 是否理解 `lint`/`run`、退出码 `2` 和规则入口 | 待真实试用 |

## 8. CLI 工程化功能需求

### 8.1 CLI 使用闭环

| 生命周期阶段 | 用户任务 | 对应入口 |
|---|---|---|
| 准备接入 | 创建 JDBC 样板或准备配置、规则和元数据文件 | `init jdbc` 或人工配置 |
| 校验资产 | 在连接/执行前发现规则结构、表字段引用等问题 | `lint` |
| 执行核验 | 对数据源运行确定性规则并生成结果 | `run` / `validate` |
| 消费结果 | 由人工、脚本或测试平台读取结果 | stdout、报告、退出码 |
| 扩展规则 | 在片段不能满足时生成并审阅候选规则 | `recommend` |

| 用户目标 | 获取可进一步配置的 JDBC 接入起点 |

| 输出 | JDBC 配置样板目录 |

| 当前状态 | `已实现` |

### 8.3 `CLI-FR-02` 配置与规则校验

| 项目 | 需求 |
|---|---|
| 用户目标 | 在执行规则前发现配置、模板或元数据引用错误 |
| 输入/触发 | `lint --config validator.yml` 或 `lint --rules rules.yml --metadata source.yml` |
| 处理要求 | 校验 schema 版本、必填信息、规则 ID、模板、表和字段引用及模板参数结构 |
| 输出 | 包含 `valid`、`errors`、`warnings` 的结构化结果，可选输出文件 |
| 验收标准 | `generic-jdbc` 和 `case5-seed` 合法配置均能返回有效 lint 结果 |
| 当前状态 | `已实现` |

### 8.4 `CLI-FR-03` 确定性校验执行

| 项目 | 需求 |
|---|---|
| 用户目标 | 以通用资产运行数据校验，不依赖 Web 页面或 AI 模型 |
| 输入/触发 | `run --config validator.yml` 或 `validate --rules ... --source ... --output ...` |
| 处理要求 | 加载配置、规则包和数据源，调用模板执行能力产生异常和汇总；JDBC 以只读方式使用 |
| 输出 | 汇总、异常、报告文件以及退出码 |
| 验收标准 | `generic-jdbc` 执行 2 条规则并检出 1 条严重异常；`case5-seed` 执行 30 条规则并输出固定结果 |
| 当前状态 | `已实现` |

### 8.5 `CLI-FR-04` 结果输出与机器消费

| 项目 | 需求 |
|---|---|
| 用户目标 | 在人工查看之外，允许脚本或流水线判断本次核验结果 |
| 输入/触发 | 执行 `run`/`validate` 并选择输出格式或 JSON 摘要 |
| 处理要求 | 输出格式语义稳定；异常检出与工具执行失败必须区分 |
| 输出 | JSON、Markdown、HTML、JUnit XML，以及 `0/1/2/3` 退出码 |
| 验收标准 | CLI 样例可产生机器可读结果；退出码 `2` 表示检出严重异常而非执行错误 |
| 当前状态 | 输出形态 `已实现`；完整质量门禁集成属于 `接入基础` |

| 当前状态 | `已实现` |

### 10.3 关键失败与降级语义

| 失败或异常场景 | 产品行为要求 | 验收口径 |
|---|---|---|
| Web 导入或 CLI 配置非法 | 返回明确问题，不将无效资产视为成功执行 | Web 加载错误提示；CLI `lint` 无效结果/退出码 `3` |
| Jar、Java、数据源或运行目录前提不满足 | 给出可定位的环境或操作提示，不掩盖运行前提 | 运行说明明确构建和 JDBC 执行目录约束 |
| 规则检出严重异常 | 正常输出异常及证据；CLI 返回 `2` 表示质量发现 | JDBC 与 Case5 样例均覆盖此语义 |
| AI 不可用、非法或违反安全约束 | 降级为本地辅助结果或拒绝不安全内容，不影响规则结果 | 展示来源/警告标识 |
| 候选生成不满足门槛 | 仅返回推荐信息和风险提示，不污染正式规则包 | `recommend` 候选人工确认要求 |
| 报告导出失败 | 展示失败信息，不能影响已经产生的确定性异常事实 | 作为运行异常处理 |

## 附录 D：CLI 契约与验收矩阵

### D.1 命令入口

| 命令 | 用户任务 | 典型输入 | 主要输出 |
|---|---|---|---|
| `init jdbc --output demo-dir` | 建立接入起点 | 输出目录 | JDBC 样板配置 |
| `lint --config validator.yml` | 校验组合配置 | validator 配置 | 有效性、错误与警告 |
| `lint --rules rules.yml --metadata source.yml` | 校验规则与字段引用 | 规则包、元数据 | 有效性、错误与警告 |
| `run --config validator.yml --json --no-report` | 执行并只返回机器摘要 | 组合配置 | JSON 摘要与退出码 |
| `validate --rules rules.yml --source source.yml --output reports` | 直接执行规则包 | 规则、数据源、输出目录 | 报告与退出码 |
| `recommend --rules rules.yml --metadata source.yml --output recommendations.json` | 生成可审阅推荐 | 规则、元数据 | 推荐结果与可选候选文件 |

### D.2 退出码

| 退出码 | 含义 | 用户应如何理解 |
|---:|---|---|
| `0` | 执行成功且未触发严重异常阈值 | 配置和运行正常 |
| `1` | 工具执行失败 | 排查环境、读取或运行错误 |
| `2` | 执行成功且发现严重异常 | 发现质量疑点，不表示程序失败 |
| `3` | 配置或规则非法 | 修正资产后再次执行 |

### D.3 输出形态

| 形态 | 用途 | 当前定位 |
|---|---|---|
| JSON 摘要/报告 | 脚本读取和结果留存 | `已实现` |
| Markdown/HTML 报告 | 人工查看与评审展示 | `已实现` |
| JUnit XML | 测试平台或流水线展示基础 | `接入基础` |
| Gate summary / 正式 CI 模板 | 完整门禁集成 | `后续规划` |

## 附录 E：结构化模板能力目录

| 模板能力 | 当前模板示例 | 适用场景 |
|---|---|---|
| 非空 | `NOT_NULL` | 主键、状态、关键业务字段必填 |
